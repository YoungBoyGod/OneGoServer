# Zap日志系统集成文档

## 概述

本文档记录OneGoServer项目中zap日志系统的集成过程。我们将原有的简单日志中间件替换为功能更强大的zap结构化日志系统。

## 修改内容

### 1. 日志中间件重构 (`pkg/middleware/logger.go`)

#### 原始实现
- 使用简单的`fmt.Sprintf`格式化日志
- 输出格式固定，缺乏结构化
- 无法根据日志级别进行分类

#### 新实现特性
- **结构化日志**: 使用JSON格式输出，便于日志分析和监控
- **日志级别**: 支持Debug、Info、Warn、Error四个级别
- **智能分级**: 根据HTTP状态码自动选择日志级别
  - 500+: Error级别
  - 400+: Warn级别  
  - 其他: Info级别
- **详细信息**: 记录更多请求详情，包括响应大小、用户代理等

#### 核心功能

1. **InitLogger(level string)**: 初始化zap日志器
   - 支持配置不同的日志级别
   - JSON格式输出
   - ISO8601时间格式
   - 可配置的采样策略

2. **Logger() gin.HandlerFunc**: Gin中间件
   - 记录所有HTTP请求
   - 计算请求延迟
   - 根据状态码智能分级

3. **GetLogger() *zap.Logger**: 获取全局logger实例
   - 供其他模块使用
   - 延迟初始化

4. **Sync()**: 刷新日志缓冲区
   - 确保日志完整写入
   - 用于优雅关闭

### 2. 服务器启动集成 (`internal/cmd/server.go`)

#### 修改点
- 在`Start()`方法中添加`middleware.InitLogger()`调用
- 在`gracefulShutdown()`中添加`middleware.Sync()`调用
- 使用配置文件中的日志级别设置

## 配置说明

### 支持的日志级别
- `debug`: 调试级别，记录最详细的信息
- `info`: 信息级别，记录一般操作信息  
- `warn`: 警告级别，记录潜在问题
- `error`: 错误级别，仅记录错误信息

### 配置文件设置 (`config/server.yaml`)
```yaml
logging:
  level: "debug"  # 设置日志级别
  format: "json"  # 日志格式
  output: "stdout" # 输出目标
```

## 优势对比

### 原有日志系统
- ❌ 文本格式，难以解析
- ❌ 信息有限
- ❌ 无法根据状态码分级
- ❌ 不支持结构化查询

### Zap日志系统
- ✅ JSON结构化格式
- ✅ 丰富的请求信息
- ✅ 智能日志分级
- ✅ 高性能（zap是最快的Go日志库之一）
- ✅ 支持日志聚合和分析工具
- ✅ 可配置的输出格式和级别

## 性能特性

- **高性能**: zap是业界最快的Go日志库
- **零分配**: 在热路径上实现零内存分配
- **结构化**: 原生支持结构化日志
- **可扩展**: 支持自定义字段和编码器

## 使用建议

1. **生产环境**: 建议使用`info`或`warn`级别
2. **开发环境**: 可以使用`debug`级别获取详细信息
3. **监控集成**: JSON格式便于与ELK、Prometheus等监控系统集成
4. **日志轮转**: 建议配置日志轮转策略避免磁盘空间问题

## 后续优化方向

1. **文件输出**: 支持日志写入文件，而不仅仅是stdout
2. **日志轮转**: 集成logrotate或类似工具
3. **链路追踪**: 集成trace ID支持分布式链路追踪
4. **性能监控**: 添加更多性能指标记录
5. **告警集成**: 根据错误日志触发告警
