# GoFrame服务器重构设计文档

## 项目概述

本文档记录OneGoServer基于GoFrame框架最佳实践的重构工作。我们将参考GoFrame的工程目录设计，但不完全照抄，而是结合项目实际需求进行适当调整。

## 目录结构设计

### 当前目录结构分析

当前OneGoServer使用传统的Go项目结构，主要问题：
1. 缺乏清晰的分层架构
2. business逻辑与基础设施代码混合
3. 缺乏统一的数据模型管理
4. 代码复用性较差

### 新的目录结构设计

基于GoFrame最佳实践，我们设计如下目录结构：

```
OneGoServer/
├── api/                    # 对外接口定义
│   └── v1/                # API版本管理
│       ├── user.go        # 用户相关API定义
│       └── common.go      # 通用API定义
├── cmd/                   # 命令行入口
│   └── server/            # 服务器启动命令
│       └── main.go        # 主入口文件
├── internal/              # 内部业务逻辑
│   ├── cmd/               # 内部命令管理
│   │   └── server.go      # 服务器启动逻辑
│   ├── consts/            # 常量定义
│   │   ├── common.go      # 通用常量
│   │   └── error.go       # 错误常量
│   ├── controller/        # 控制器层
│   │   ├── user.go        # 用户控制器
│   │   └── health.go      # 健康检查控制器
│   ├── dao/               # 数据访问层
│   │   ├── user.go        # 用户数据访问
│   │   └── base.go        # 基础数据访问
│   ├── model/             # 数据模型
│   │   ├── do/            # 领域对象(自动生成)
│   │   └── entity/        # 数据实体(自动生成)
│   ├── service/           # 业务逻辑层
│   │   ├── user.go        # 用户业务逻辑
│   │   └── interface.go   # 业务接口定义
│   └── logic/             # 业务逻辑实现
├── manifest/              # 部署清单
│   ├── config/            # 配置文件
│   │   ├── config.yaml    # 主配置文件
│   │   └── docker.yaml    # Docker配置
│   └── deploy/            # 部署文件
├── pkg/                   # 公共包
│   ├── response/          # 响应处理
│   ├── middleware/        # 中间件
│   └── utils/             # 工具函数
├── utility/               # 工具类
└── go.mod                 # 依赖管理
```

## 核心特性

### 1. 分层架构
- **API层**: 定义对外接口结构
- **Controller层**: 处理HTTP请求和响应
- **Service层**: 业务逻辑实现
- **DAO层**: 数据访问抽象
- **Model层**: 数据模型管理

### 2. 依赖注入
使用依赖注入容器管理组件生命周期

### 3. 配置管理
统一的配置管理，支持多环境配置

### 4. 中间件支持
标准化的中间件实现

## 实现计划

1. **第一阶段**: 重构目录结构和基础框架
2. **第二阶段**: 实现核心业务逻辑
3. **第三阶段**: 添加中间件和扩展功能
4. **第四阶段**: 性能优化和测试
