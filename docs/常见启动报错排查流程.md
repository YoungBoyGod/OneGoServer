# 常见启动报错排查流程

## 1. 现象描述

- 程序启动或运行时出现调用栈（stack trace），但缺少最上方的具体报错内容。
- 仅有函数调用链，无法直接定位问题。

## 2. 排查建议

1. **查看完整报错内容**
   - 重点关注最上方的 error 或 panic 信息。
   - 例如：`panic: xxx`、`runtime error: xxx`、`open logs/xxx.log: permission denied` 等。
2. **检查日志目录和权限**
   - 日志目录是否存在：`ls -l logs`
   - 当前用户是否有写入权限。
   - 配置文件中的日志路径是否正确。
3. **检查配置文件**
   - `config/server.dev.yaml` 日志相关配置项。
   - 路径、文件名、格式等。
4. **补充报错信息**
   - 若无法定位，请将完整的终端报错内容（尤其是最上方几行）贴出。

## 3. 排查流程图

```mermaid
flowchart TD
    A[出现调用栈] --> B[查看最上面报错内容]
    B -- 日志相关 --> C[检查日志目录和权限]
    B -- 其他panic --> D[根据panic内容定位代码]
    C --> E[修复权限或路径]
    D --> E
    E --> F[重启服务验证]
```
